# 风险与限制

| 风险或限制 | 当前影响 | 当前为何可接受 |
|---|---|---|
| 雨量标签依赖`rainfall * 0.1`及“记录表示前一分钟”的设备解释 | 更换雨量计或固件后可能产生系统性标签偏差 | 现有模型、数据集和在线展示使用同一规则，当前设备内口径一致 |
| 默认`stratified_all`随机分层而非纯时间划分 | 相邻天气过程可能跨集合，指标可能乐观 | 用于当前工程验证；代码另支持`time`和`event_holdout`，论文或外部验收应补时间外测试 |
| 有雨分钟仅1,256/26,409 | 分类和强降雨回归仍受长尾影响 | 训练保留全部有雨样本并动态下采样无雨，验证/测试保持原分布，指标同时报告rainy MAE和F1 |
| 002/003使用链路Z-score域适配和迁移权重 | 不等价于独立标注训练，跨终端一致性不保证 | 可在缺少新终端标注时先提供分钟反演；页面明确分终端展示，后续可替换独立权重 |
| 位置数据可能缺失或错误 | 完整位置模型无法覆盖所有分钟 | 001配置无位置回退模型；服务记录`inference_mode`和位置来源，但回退精度低于完整输入的可能性仍存在 |
| 图像标签可能延迟、缺失或分类错误 | 视觉四维信息质量变化 | 无匹配图像时明确使用零向量和`image_available=0`，核心链路/位置/气象仍可推理 |
| 不能将`SNR >= -10 dB`直接硬过滤全部数据 | 会大量丢失雨天和强降雨窗口 | 当前部署不硬过滤，只在页面高亮；保留质量视图供固定划分消融 |
| SQLite和单进程FastAPI不是高可用架构 | 大范围首次历史推理可能阻塞，缺少集群故障转移 | 当前是单站点科研原型，历史物化和时间轴缓存降低重复计算；尚不面向公网SLA |
| 服务没有认证授权 | `0.0.0.0:8041`暴露后存在访问风险 | 当前部署在受控内网；对外部署前必须增加反向代理、认证和访问控制 |
| Shell脚本包含本机绝对路径 | 换机器后不能原样启动 | 所有路径集中在两个入口脚本，交付时逐项修改即可；`check_delivery.py`会在启动前发现缺失文件 |
| 原始库、照片、权重和历史库不提交Git | 克隆后能训练和评估固定数据，但不能直接启动完整在线服务 | Git内置固定NPZ和视觉标签；服务部署仍需三套权重、视觉权重、照片和必要SQLite |
| 历史表名仍为`rain_retrieval_passes` | 名称与分钟语义不一致 | 为兼容现有8041历史库保留，仅是存储命名，不改变每条记录的一分钟语义 |

当前系统适合：固定设备和数据口径下的研究验证、内网Demo、离线实验及分钟级趋势观察。它还不是经过跨地域、跨季节、跨硬件验证的生产级降雨计量系统。
