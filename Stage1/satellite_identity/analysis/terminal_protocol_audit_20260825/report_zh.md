# 三终端卫星协议 ID 与物理身份审计（2026-08-25）

## 结论

002/003 的卫星协议 ID 均按 `trackNo * 256 + phaseNo` 重建。三终端应用同一
LET 版本时间边界和同一套历史规范化映射后，没有发现需要接受的异号映射。
相同协议 ID 可直接视为同一协议星；同一分钟出现的不同 ID 不能视为同一颗
物理卫星。

| 终端组合 | 重叠分钟 | 至少共享一个相同 ID 的分钟 | 比例 | 分钟 ID 集合 Jaccard |
|---|---:|---:|---:|---:|
| 001–002 | 11,412 | 5,394 | 47.27% | 0.4037 |
| 001–003 | 6,342 | 2,693 | 42.46% | 0.3711 |
| 002–003 | 8,110 | 8,060 | 99.38% | 0.9734 |

002 与 003 几乎始终选择同一颗协议星。001 与新终端只在约一半重叠分钟选择
相同 ID，说明老终端和新终端的调度/选星策略不同；这不是 ID 编码不一致。
同一分钟可能有多颗卫星可见，因此时间共现只能生成待核验候选，不能单独
作为改号依据。本次没有将任何异号共现候选写入运行映射。

## Space-Track 物理身份复核

轨道匹配联合使用最新 LET、Space-Track 历史 GP/TLE、终端 ECEF 轨道状态和
上海站 PHY 可见性。复核中发现历史 PHY 的 `bdtTime` 存在长时间卡滞：抽样
仅约 53% 的记录与接收端 `localTime` 相差不超过 5 s。因此，PHY 可见性改用
北京时间 `localTime` 转 UTC；ECEF 坐标仍使用其对应的 `bdtTime`；LET 内部
轨道历元继续按 BDT 解析。

最新 LET 的 211 个协议 ID 中，117 个达到严格 `accepted` 标准，94 个仍需
确认。与上一版严格清单相比，本次通过亚公里级 ECEF 轨道残差新增确认 ID
`0, 784, 1037, 1041, 1043, 1045, 1051, 1055`；同时将 7 个只依赖旧 PHY
时间可见性的条目降级复核。ID `1049` 的新实测 ECEF 证据指向
`NORAD 69807 / QIANFAN-208`，其中位 ECEF 残差为 0.568 km、相对第二候选
间隔为 401.1 km，替代旧的纯可见性候选 `QIANFAN-210`。

协议 ID `0` 在 LET 中存在，但分钟反演的数据清洗会把 `(trackNo, phaseNo) =
(0, 0)` 作为无效测量排除，因此三终端实际观测集合中有 116 个已确认物理
卫星 ID。其余 ID 缺少有效 ECEF、存在多个轨道兼容候选或不属于最新 LET
目录，暂不强制归并。

## 分钟反演状态

8041 服务已对三台终端执行一分钟窗口反演，且 002/003 使用上述协议 ID
公式。当前独立历史库包含：001 为 45,174 条、002 为 9,145 条、003 为
3,760 条分钟结果。003 的原始链路数据截至 2026-07-07，因此之后不会产生
新分钟结果。位置匹配继续要求规范化后的 PHY ID 与 position ID 相同，并在
5 s 内做最近邻匹配；无法匹配位置的窗口由无位置后备模型处理。
