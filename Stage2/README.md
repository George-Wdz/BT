# Stage2: Time-Series Forecasting

[English](README.md) | [中文](README_CN.md)

Stage2 forecasts future rainfall on a regular time grid. The forecasting backend is the third-party GPT4TS / One Fits All implementation, which is used locally but not vendored into this repository.

Upstream project:

```text
https://github.com/DAMO-DI-ML/NeurIPS2023-One-Fits-All
```

## Input

Stage2 consumes CSV files generated by Stage1.5. The table follows the GPT4TS `Dataset_Custom` format:

```text
date, feature_1, ..., feature_n, target
```

Typical target columns:

| Target | Meaning |
| --- | --- |
| `rain_10min_mm` | Accumulated rainfall over the previous 10 minutes. |
| `rain_1h_mm` | Accumulated rainfall over the previous 1 hour. |

## Role in This Project

Stage1 estimates rainfall from satellite passes. Stage1.5 aggregates pass outputs and weather-station measurements into regular buckets. Stage2 learns temporal forecasting from that structured table.

The third-party GPT4TS code is kept outside this repository to preserve upstream ownership and reduce repository size. See `THIRD_PARTY.md` for dependency notes.

## Example

From the local GPT4TS checkout:

```bash
cd /home/wdz/BT/Stage2/GPT4TS/Long-term_Forecasting
python main.py \
  --root_path ./datasets/weather/ \
  --data_path stage1_5_weather_10min.csv \
  --target rain_10min_mm \
  --features S \
  --freq 10min \
  --model_id stage1_5_rain_10min \
  --data custom
```

Notes:

- `features=S` uses the target column as a univariate forecasting baseline.
- `features=M` predicts all numerical columns in the original GPT4TS implementation.
- A strict “multivariate input, single rainfall output” setting may require a small data-loader or training-loop adjustment.
